# DATARAG

デジタル化・AI導入補助金2026の要件・手続きを調べるためのRAGシステム。

公募要領と交付規程を横断検索し、クロスエンコーダによるリランキングを経て回答を生成します。
根拠が不足する場合は生成せず「この情報からは判断できません」と返します。

> **ステータス: 構築中。** インフラ（Voyage / Neon / Claude API）は疎通確認済み。
> アプリケーションコードは未実装です。進捗は [`PROGRESS.md`](PROGRESS.md) を参照。

## なぜこのテーマか

補助金の公募要領は、枠ごとに別文書として発行され、文言は似ているが要件は異なります。
さらに**交付規程**（法的拘束力のある規程）が**公募要領**（申請手引き）より上位にあり、
両者が矛盾した場合は交付規程が優先されます。

素朴なRAGはこの構造で壊れます。表層的に類似したチャンクを別々の枠から寄せ集め、
どの枠・どの階層の文書に基づく回答なのかを示さないまま、自信たっぷりに答えてしまう。
本システムはその失敗モードに正面から対処することを目的としています。

## アーキテクチャ

```
インジェスト:
  PDF → Docling HybridChunker → Voyage AI (voyage-3.5) → Neon / pgvector

クエリ時 (Pydantic AI エージェント、ツール2つ):
  ├─ search_knowledge_base(query)
  │    ベクトル検索で上位20件 → クロスエンコーダで再スコアリング → 上位5件
  │
  └─ retrieve_full_document(title)
       タイトル指定の全文取得。チャンク単位では文脈が足りない質問向け

  どちらを呼ぶかはエージェントが判断する。

  生成の直前: 最高リランクスコアを閾値と比較。
  閾値未満なら生成をスキップして「判断できません」を返す ← ハードゲート
```

**このゲートはエージェントの裁量ではありません。** どのツールが呼ばれたかに関わらず、
生成の前に無条件で実行されます。エージェントに「分からないときは答えるな」と
プロンプトで指示するのは、保証ではなくお願いにすぎないためです。

## 技術スタック

| 層 | 選定 | 理由 |
|---|---|---|
| チャンク分割 | Docling `HybridChunker` | 固定長分割では表と条番号が切れる |
| 埋め込み | Voyage AI `voyage-3.5` (1024次元) | 日本語性能。Anthropicは埋め込みAPIを持たない |
| ベクトルストア | Neon (Postgres + pgvector) | 自動停止なし。デモ日程に合う |
| リランキング | クロスエンコーダ (ローカル実行) | 多言語モデル。後述の設計判断を参照 |
| エージェント | Pydantic AI | ツール選択層だけを抽象化し、検索の判断は隠さない |
| 生成 | Claude API (`claude-sonnet-5`) | |
| 配信 | FastAPI (`/query`) | |

## コーパス

公開されている公的文書14件、372ページ、約363,000文字。全件テキストレイヤーあり（OCR不要）。
出典URL・ページ数・SHA-256は [`data/raw/MANIFEST.md`](data/raw/MANIFEST.md) に記録。

| 区分 | 件数 | 内容 |
|---|---|---|
| 公募要領 | 5 | 通常枠 / インボイス枠（対応類型・電子取引類型）/ セキュリティ対策推進枠 / 複数者連携枠 |
| 交付規程 | 5 | 上記5枠に対応する規程（公募要領より上位） |
| 加点項目一覧 | 1 | 審査加点の基準 |
| スマート農業関連 | 3 | **制度をまたぐ質問の失敗パステスト用** |

スマート農業の3件（#2〜#4）はデジタル化・AI導入補助金2026の文書ではありません。
「DX補助金とスマート農業補助金を併用できるか」という、**どの文書にも答えの存在しない質問**を
投げたときに、システムが推測せず回答を拒否できるかを検証するために意図的に含めています。

前年度（2025/2024/2023）のアーカイブは除外しています。年度をまたいで混在させることが、
補助率・補助上限額を自信たっぷりに間違える最短ルートだからです。

## 設計上の判断

**`source_doc` に枠名を持たせる。** 5つの公募要領の字句上の重複は低い（Jaccard 0.5〜5.3%）
一方で、意味的な重複は高い（同じ概念・同じ語彙）。チャンクがどの枠由来かを保持しないと、
検索結果は容易に枠をまたいで混ざります。

**`doc_type` で権威階層を表現する。** 交付規程が公募要領に優先するというルールは、
チャンク自身がどちらの種別かを知らなければ生成時に適用できません。

**リランカーは多言語モデルを使う。** 一般的な既定値である `ms-marco-MiniLM-L-6-v2` は
英語で学習されており、100%日本語のコーパスではリランキング段が実質的に機能しません。
`BAAI/bge-reranker-v2-m3` を採用予定です。副次的な利点として、シグモイドを通して
0〜1に収まるため、拒否閾値を「解釈可能な数値」として較正できます
（ms-marcoの出力は範囲の定まらないロジット）。

## セットアップ

```bash
git clone https://github.com/Nekta1991/DATARAG.git
cd DATARAG

python -m venv .venv
.venv/Scripts/activate        # Windows  (macOS/Linux: source .venv/bin/activate)
pip install -r requirements.txt   # ※ 未作成

cp .env.example .env
# .env に Voyage / Anthropic / Neon の値を記入
```

必要な認証情報は3つ: Voyage AI、Anthropic、Neon（Postgres接続文字列）。
`.env.example` に各キーの取得先と、設定値の意味をコメントで記載しています。

**コストについて:** 課金が発生するのはClaude APIの生成のみ（1クエリ約$0.011）。
Voyageの埋め込みは無料枠200Mトークンに対しコーパスが約302kトークンなので$0、
Neonは無料枠、リランキングはローカル実行です。

## ライセンスと出典

`data/raw/` に含まれるPDFは、経済産業省・中小企業庁・農林水産省が公開している
公的文書です。各文書の出典URLと取得日は `MANIFEST.md` に記録しています。
本リポジトリのコードと当該公的文書の権利は別個のものです。
